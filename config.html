The languageConfig (GraphQL & middleware)

Config (GraphQL & middleware)

Config statements set the per-database singletons — the GraphQL interface's shape, global API-endpoint defaults, and the server's default namespace/database. They have no name: the variant is the header, and there is no /// doc comment (no COMMENT clause exists — use a plain // line instead).

GraphQL: expose tables and functions

The GraphQL interface defaults to exposing nothing. Switch it on explicitly:

auto; sets both families — tables and functions — to auto-expose. Or curate the surface with include/exclude lists:

  • tables:/functions: each take auto, none, or a sub-block with exactly one of include:/exclude:.
  • depth: and complexity: bound query cost.
  • introspection: defaults to auto — none; hides the schema from clients.

A note on round-trips

Configs are singletons — re-defining is what OVERWRITE is for, and the compiler always emits it. The database reports configs as header-less fragments (GRAPHQL TABLES … FUNCTIONS …), not full statements; the reverse reader reassembles them, so normalize folds them back into your file faithfully.
