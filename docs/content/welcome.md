Surform is a schema language for SurrealDB — a small, readable way to
describe the tables, fields, indexes, events, and access rules your
application needs, in one file you can read, review, and version like
code.

The `surform` compiler turns that file into SurrealQL DDL — the
`DEFINE` statements SurrealDB applies. And because a schema file
drifts from the database it describes, Surform reads the database's
INFO report back the same way: it compares what it finds with what you
declared and tells you what changed.

## The loop

Working with Surform is the infrastructure-as-code loop:

1. **Declare** — describe the schema you *want* in `schema.surdl`.
2. **Check** — `surform check schema.surdl` validates it and explains
   anything it doesn't understand, with a pointer at the line.
3. **Build & apply** — `surform build schema.surdl` emits DDL. Run it
   through `surreal sql`, your SDK, or any migration runner. Every
   emitted `DEFINE` carries `OVERWRITE` (a credential-less user
   defines once), so applying again is safe: the database *converges*
   to the file.
4. **Converge** — later, `surform migrate generate schema.surdl
   --info …` compares the file with the database's INFO output and
   prints both the drift and the script that converges the database
   to the file.

## What Surform covers

| command | what it does |
|---|---|
| `surform check` | parse a schema file, report line-anchored diagnostics |
| `surform build` | emit the SurrealQL DDL |
| `surform fmt` | print (or rewrite) the file in the canonical style |
| `surform normalize` | merge the database's state back into the file — how you *adopt* an existing database |
| `surform migrate generate` | what changed between file and database, plus the script that converges it |
| `surform migrate commit` / `push` / `status` / `revert` | the migration pipeline: hash and ledger-record a filled draft, apply committed migrations in number order, compare the directory against the live ledger, draft a revert |
| `surform lint` | advisory warnings — world-open tables, plaintext passwords, and other common traps |
