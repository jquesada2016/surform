Params & sequences

Params and sequences are the two small database-side values a schema often needs: named constants and counters.

Params: define-time constants

A param is a $-named value evaluated once, when the schema applies — the result is stored, not the expression:

The value is any SurrealQL expression — including an object literal, since the { after = is just the value's first character:

The define-time-freeze has a flip side: an expression like time::now() evaluates once, at apply, and the result is what the database stores — so $t reads as the moment the schema went on, not the moment you query it. (Watch the braces, too: { time::now() } is a one-element set, not a call.) Re-applying the emitted DDL freezes a fresh timestamp each time.

Sequences: monotonic counters

A sequence hands out ever-increasing numbers — invoice numbers, order ids — distributed-safe and never rolled back, even in failed transactions. Clients consume it with sequence::nextval('name'):

The short form sets the start value. The block form tunes the rest: batch: (how many values each node reserves at a time — the distributed-safety margin) and timeout: (the per-query acquisition limit):

With defaults everywhere, the bare form is the whole declaration — and normalize returns it that short, folding the database's verbose BATCH 1000 START 0 away:
