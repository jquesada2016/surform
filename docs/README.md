# docs/ — the Surform documentation site

The user-facing documentation, deployed on GitHub Pages. The site is
generated by running the tool: every SDL example is parsed by the
compiler and, where the fence asks for it, applied to an in-process
SurrealDB 3.3.0 engine — and a broken example fails the build
(`content/verification.md` describes the pipeline, and is itself part
of the site).

## Layout

| path | what it is |
|---|---|
| `content/*.md` | the pages (a small markdown subset; custom verified fences) |
| `examples/*.surdl` | files the walkthrough pages and terminal transcripts run — the single source of truth those fences share via `src=NAME` |
| `src/main.rs` | `docgen`: builds the site, captures CLI help, writes `docs/_site/` |
| `src/verify.rs` | the verification pipeline (fence kinds, exec, drift scenarios) |
| `src/md.rs` | the markdown subset renderer |
| `src/site.rs` | page table, shell, panels |
| `src/specpage.rs` | spec-page preparation (link rewriting for the repo's `spec/*.md`) |
| `src/playground.rs` | the playground page (see below) |
| `src/hl.rs` | build-time syntax highlighting |
| `assets/` | HTML template, stylesheet, progressive-enhancement JS |
| `editor/` | the playground's JS source + build (see below) |

The **Language spec** nav group renders the repo's `spec/*.md` — the
source of truth — through this same pipeline: their labeled fences
(`sdl` / `sdl-body` / `sdl no-exec`, documented in spec/README.md) are
verified and go live exactly like `content/`'s, and
`tests/spec_examples.rs` checks the same fences per commit.

## The playground and the interactive examples

`playground.html` runs the compiler in the browser: the
`surform-editor` crate (workspace member `editor/`) compiles to
WebAssembly, and `editor/src/main.js` (CodeMirror 6) wires its
`check()`, `fmt()`, and `lint()` into a live editor — squiggles, the
diagnostics list (compile errors first, lint advisories under them),
the DDL and canonical panels, and a Format button that rewrites the
buffer with the canonical form. The page is generated like every other
(`src/playground.rs`): it stamps in the compiler's own keyword table
(for highlighting) and the verified `examples/*.surdl` files (the
loader's menu; `broken.surdl` must stay broken, the others must parse
clean — a deviation is a build error), and it fails the build when
the wasm bundle is missing.

The same bundle drives the docs pages: every `sdl`, `sdl-error`,
`sdl-lint`, and `sdl-fmt` fence is stamped with a JSON island (the
verified fence text) and rendered with a Reset/Format toolbar — the
static highlighted panels hydrate into editors as they scroll into
view, and the DDL, diagnostics, and lint panels recompute live in
the browser (the DDL pane is inked client-side by the official
grammar, `@surrealdb/lezer`, and so are the editors' embedded
SurrealQL regions — found by `docs/editor/src/surrealql-regions.js`).
The canonical panel is the exception: it shows the engine's own
record (the merged readback the builder computed), which the browser
cannot reproduce, so it keeps the build-verified text.
The walkthrough kinds (`adopt`, `drift`, `session`) stay static
transcripts — they demonstrate the native CLI. Build-time
verification is unchanged: a fence that stops matching its claim is
still a build error, and the island text is exactly what the build
verified (Reset restores those bytes).

The bundle is a committed artifact (no CI), and its file names carry a
content hash (`editor.<hash>.js`, `surform_editor_bg.<hash>.wasm`,
with the name recorded in `assets/editor/bundle.txt` for docgen) — a
changed compiler or app changes the hash, so browsers refetch instead
of serving stale behavior. The wasm **embeds the compiler**: a lint
flip, an emission fix, any compiler change at all only reaches the
site when the bundle is rebuilt. It is rebuilt from the current
sources on every deploy (`deploy.sh` runs the build below), and must
be rebuilt and committed with any change that touches the compiler,
the binding, this app, or anything wasm-size-relevant:

```sh
cd docs/editor
npm install        # once
RUSTFLAGS="--remap-path-prefix=$HOME=/build" node build.mjs
                   # cargo (wasm32) → wasm-bindgen → wasm-opt -Oz → esbuild;
                   # the remap keeps the building machine's home path out of
                   # the committed wasm's embedded panic locations
```

Outputs land in `assets/editor/` (`editor.js`, the bindgen glue, the
`-Oz` wasm) and are committed with the change that produced them. The
JS side's pure helpers (`editor/src/positions.js`) self-check in
plain Node: `node docs/editor/src/positions.js`.

Testing note: embedded/preview browsers may suspend rendering frames
for background tabs — IntersectionObserver never delivers there, so
hydration silently doesn't run. Test with the pane visible and
foregrounded.

## Fence kinds (in `content/*.md`)

| fence | behavior |
|---|---|
| ` ```sdl ` | verified example: parse → emit → exec → panels (SDL + DDL) |
| ` ```sdl no-exec ` | engine-gated shape: parse + emit only, badge says so |
| ` ```sdl info ` | adds the canonical readback panel (INFO → merge → canonical SDL) |
| ` ```sdl no-ddl ` | hides the DDL panel |
| ` ```sdl src=NAME ` | body lives in `examples/NAME.surdl` (shared with sessions) |
| ` ```sdl-error expect=SDL-E1044[,…] ` | must produce exactly those diagnostic codes; panels show the render |
| ` ```sdl-lint expect=SDL-L0003[,…] ` | same, for lint findings |
| ` ```sdl-lint expect=none ` | the suppression flavor: the linter must report NOTHING |
| ` ```sdl-fmt ` | shows authored vs canonical form; asserts the fmt fixed point |
| ` ```adopt ns=… db=… ` | the body is rendered INFO text; shows the normalize adoption |
| ` ```drift scenario=… ` | apply → mutate by hand → compare + convergence script (baseline must converge) |
| ` ```session cmd=check src=NAME [exit=1] ` | runs the `surform` binary against `examples/NAME.surdl`, captures the transcript |
| ` ```cli-help cmd=build ` | embeds the binary's captured `--help` |
| anything else (`sh`, `text`) | plain highlighted code, no verification (never fake *output* — use sessions) |

## Building

```sh
# from the repository root
cargo build --bin surform
cargo run -p surform-docs -- --out docs/_site --cli target/debug/surform
```

`--out` defaults to `docs/_site`; `--cli` defaults to
`target/debug/surform`. The build exits nonzero and prints
`file:line — reason` for every failing example.

## Deploying to GitHub Pages

The output is a fully static bundle (works from any subpath; no
Jekyll — `.nojekyll` included). Deploy by pushing it to the
`gh-pages` branch:

```sh
docs/deploy.sh            # or: docs/deploy.sh --release
```

One-time GitHub setup: **Settings → Pages → Source: Deploy from a
branch → `gh-pages` → / (root)**. If the repository has no `origin`
remote yet, add one first (`git remote add origin
git@github.com:jquesada2016/surform.git`) — deploy pushes there, and
the site's "Edit this page" links derive from it.

## Editing notes

- Pages are listed in `src/site.rs`'s `pages!` table — that table is
  the navigation and the build order; a page file missing from disk
  fails the build.
- Markdown subset: headings `##`–`####`, paragraphs, lists (one
  nesting level), pipe tables, `>` callouts, fences, inline
  code/bold/italic/links. Pages do **not** write their own `#` title
  — the shell injects it from the page table.
- The mini-renderer and highlighter carry unit tests
  (`cargo test -p surform-docs`); the verification pipeline is
  exercised by the build itself.
