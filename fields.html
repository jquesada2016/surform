The languageFields

Fields

Fields decide what a record may hold — and what the database does with values on the way in. The type sits right in the header (name: type); everything else is a clause in the block.

A field, standalone and nested

Inside a table block you write name: type. At top level the same field takes an on: line naming its table — both spellings emit the same DEFINE FIELD:

The nested spelling is the everyday one (the table page shows it in context); the standalone form is how the database itself reports fields, and it reads back into nested form on normalize.

Controlling values: default, value, assert

  • default: fills the value in when the create leaves it out.
  • default always: fills it in even when a value was supplied.
  • value: overrides whatever was supplied, every time.
  • assert: is a predicate every write must satisfy — $value is the incoming value, and throw inside lets you customize the error.

$value inside ['open', 'closed'] is ordinary SurrealQL — the full function library is available in every expression clause.

References: what happens when the target dies

Any field whose type is a record can declare how SurrealDB reacts when the referenced record is deleted:

reference; alone means ignore (the engine's default, and what it always prints back). The strategies are reject, cascade, ignore, unset — or a custom SurrealQL block that runs instead. Inline payloads (SurrealDB 3.3)

inline; on a field of a relation table embeds that value into the edge-adjacency payloads, so filtered traversals like ->likes WHERE score > 5 run without fetching edge records:

The host must be a relation table, the name must be top-level (not id/in/out, not dotted), and computed fields can't be inline — there is nothing stored to embed:

A table carries at most 255 inline fields; the linter counts them for you (SDL-L0020).
