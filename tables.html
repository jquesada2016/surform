The languageTables

Tables

Tables are the largest unit of a schema file: the kind of the table lives in the header, and everything else — permissions, changefeeds, nested fields and indexes — lives in the block.

The everyday table

A bare table is a normal table, and the DDL says so even when you don't — TYPE NORMAL is always emitted, because a normal table rejects SurrealQL's RELATE statements:

The third panel is the round trip: the DDL was applied to an in-process SurrealDB 3.3.0 engine, its INFO report read back, and the canonical form is what Surform writes from that — engine-side defaults (PERMISSIONS NONE, the explicit TYPE NORMAL) elide again.

schemafull (records must match their declared fields) or schemaless (records may carry anything) — the schema flag is always emitted, either way. You can also spell it in the header: table user schemafull { … }; is the same table.

Relations and graph edges

Relations get their own page — Relations — because the arrow forms, enforced, and the 3.3 lightweight edges have a lot to say. The one-line version:

from -> edge -> to, spelled in RELATE's own order, with enforced checking that both endpoints exist on every edge.

Permissions: the default is NO

A table with no permissions clause denies record users everything. That default is stored (PERMISSIONS NONE in the database's record) — omitting the clause is the secure default, and the linter never warns on it. What the linter does warn on is the opposite extreme, permissions: full;, which hands the table to everyone. The per-operation form scopes each operation independently, and unlisted field operations default the other way — to FULL:

Unlisted operations are none for tables. Operations can be comma-grouped when they share a value, and the whole clause has a one-line shorthand (permissions: full;) when every operation gets the same answer. Expressions are real SurrealQL — $auth is the signed-in record.

Lifecycle: drop and changefeed

drop; tells the server to silently skip storing, indexing, and edge-linking anything written to the table — useful to keep history flowing without keeping data. changefeed keeps a change log for the given duration; include original; stores each change's before-image. (Durations print value-normalized — 30d appears as 4w2d in the DDL, SurrealDB's canonical decomposition. The value is identical.)

Views: the block is the query

A view is a stored, read-only query pretending to be a table. There is no clause key — the block's first statement is the SELECT itself, validated by SurrealQL's own parser:

Views always emit as TYPE ANY SCHEMALESS AS SELECT …. A view reads other tables — build orders the view after them in the emitted DDL, so the view may stand anywhere in the file (a view chain that reads itself is the SDL-E0015 error — who owns the order).
