The languageFunctions

Functions

Functions are stored SurrealQL procedures — callable from queries, other functions, events, and permission expressions. The keyword is fn; parameters keep their $; the body is real SurrealQL.

The shape

Reading it: the signature fn name($param: type) -> return_type, then a brace block with the body, then — optionally — a second brace block with ordinary clauses (permissions:, GraphQL hints). It is the one statement with two blocks.

The body's last statement, without a trailing ;, is the return value:

Zero-parameter functions are legal (fn ping() { … };), and the body is re-emitted in the engine's canonical form — the compiler hands your SurrealQL to the official parser and prints its result, so a stored body and your file agree after a round-trip.

Permissions

Functions default to permissions: full — anyone who can run queries can call them. Lock them down per function:

permissions: takes none, full, or an expression (which the compiler emits as PERMISSIONS WHERE …).

Names with segments, GraphQL hints

Names may carry :: segments — fn util::slugify(…) defines fn::util::slugify. The name never spells the prefix itself — the fn keyword carries it, so fn fn::weird(…) is an error (SDL-E1075): spelled as written it would define fn::fn::weird, a different function. GraphQL hints ride the second block:
