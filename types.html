Types (kinds)

Every field's type is SurrealDB's own kind grammar, passed through verbatim — Surform adds no spellings and hides none. (The one addition is the compile-time type alias: a named kind a Capitalized word references.) This page covers the shapes you'll use most; SurrealQL's kind grammar is the complete reference.

Scalars

number accepts both ints and floats; decimal is the exact-base-10 type for money.

Option: "or nothing"

option<T> marks a field the record may leave out. It is equivalent to the union none | T — SurrealQL's parser desugars one into the other, Surform knows they are the same type, and the canonical spelling is always option<T>:

How types compare

Two spellings that parse to the same kind are the same type: option<string> ≡ none | string, int | int ≡ int, and unions compare flattened and deduplicated. This matters when you normalize: the database prints its desugared view (none | string), and the compiler folds it back to the option<T> you meant — your file doesn't churn when the database round-trips it.
