Indexes

Indexes make lookups fast and rules enforceable. The index kind sits in the header — unique, count, fulltext, hnsw, diskann — and each kind brings its own clauses.

The everyday two

A plain index is a lookup; a unique index is a rule:

fields: takes an expression list — usually plain field names, comma separated. (SurrealQL's COLUMNS spelling is accepted as an alias.)

concurrently; builds the index in the background — a build-time directive only; the database doesn't remember it.

Standalone or nested

Fulltext: search over text

A fulltext index covers exactly one field, through an analyzer (the default analyzer applies when you omit the rest):

The pieces: analyzer: names an analyzer; bm25: is the scoring pair; highlights; enables highlighting in query results. At the defaults the clause disappears — index fulltext body_fts { fields: body; }; is the complete minimal form, and the database's verbose default printout folds back to it on normalize. Authoring order between an analyzer and the index that names it does not matter: surform build orders the emitted DDL itself — the analyzer lands before the fulltext index that names it — so the define-time hazard never arises (a true dependency cycle is an error, not an ordering warning).
