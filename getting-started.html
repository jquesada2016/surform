Getting started

This page takes a small schema from an empty directory to a compiled, apply-ready script.

Install

Surform is a single Rust program with no runtime dependencies. You need the Rust toolchain (rustup installs it in one command), then clone this repository and build the compiler:

sh
cargo install --path .

That puts the surform binary on your PATH. Check it:

textcaptured output — the real thing, not prose

Usage: surform [OPTIONS] <COMMAND>

Commands:
  check      Parse an SDL file and report diagnostics
  build      Compile an SDL file to SurrealQL DDL
  fmt        Write an SDL file's canonical form
  normalize  Merge rendered INFO interchange into an SDL file and re-emit the canonical SDL
  migrate    Schema migrations — generate, commit, push, status, revert
  lint       Lint an SDL file — advisory findings, exit 1 when any exist
  help       Print this message or the help of the given subcommand(s)

Options:
      --json     Render diagnostics as JSON (one object per line) instead of the graphical format
  -h, --help     Print help
  -V, --version  Print version

The schema

Here is the quick-start schema — a shop with users and posts. This is examples/shop.surdl in the docs sources; every panel on this page is produced from this file. The examples on these pages are editable: the verdict and the DDL recompute as you type, and Reset brings the verified text back.

  • /// doc comments become the definition's COMMENT in SurrealDB — your documentation travels with the schema.
  • field email: string { assert: … }; — anything after : is SurrealQL, checked by SurrealDB itself. Surform does not invent a second expression language.
  • index unique email_unique is nested inside its table, the way you think about it; the compiler emits the standalone DEFINE INDEX SurrealDB expects.
  • field author: record<user> is a graph-style reference — types pass through verbatim.

Compile it

build prints the SurrealQL DDL to stdout — pipe it to a file, to surreal sql, or to your deployment pipeline:

Two conventions the output relies on:

  • Every emitted DEFINE carries OVERWRITE (one exception: a user with no credential defines once — Users & roles). Applying the script twice — or applying it over a database that already has some of the definitions — redefines cleanly instead of erroring. Your schema file is the desired state; applying it converges the database to it.
  • After each DEFINE NAMESPACE / DEFINE DATABASE the compiler emits the matching USE line, so one script crosses namespace and database boundaries safely (a database with no preceding namespace omits the USE).

Apply it

The build output is ordinary SurrealQL — run it anywhere SurrealDB 3.3 runs. For example, with the SurrealDB CLI installed:

sh
surform build schema.surdl > schema.surql
surreal sql --conn ws://localhost:8000 --user root --pass … --ns acme --db shop < schema.surql

Surform itself never touches your database connection — it produces the script, your existing tooling applies it. (Adopting a database — the reverse trip — is one command.)
